## 1. Folder layout

```
copy-project/

  01-research.md        language bank, competitors, proof, gaps
  02-positioning.md     positioning, angles, "only" claim
  03-offer.md           offer, pricing, guarantee
  04-messaging.md       message house, voice, objection map

  06-sales-kit.md       scripts, outreach, objections, follow-ups
  07-test-plan.md       ranked tests, hypotheses, metrics
  08-learning-log.md    results and insights over time
```

Write `README` style headers at the top of each file with date and status (draft / approved). Keep one source of truth; do not duplicate content across files, link to it.

## 2. Quick-mode micro-brief

Before writing a small asset, settle these in 5 lines (write them at the top of your answer if helpful):

```
Reader: [who, situation]  |  Awareness: [1-5]
Promise: [one sentence]   |  Proof: [one real item or NEEDS PROOF]
Objection to answer: [one]|  Action: [one]
Channel + constraints: [format, length, language, tone]
```

Then deliver 3 to 5 variants on different angles with a recommended pick.

```markdown
Subhead:
Body:
CTA:

### Variant B - [Angle]
...

### Variant C - [Angle]
...

**Recommendation:** A, because ... Would change if ...
**Scorecard:** 43/50. Fixes made: ...
**[NEEDS PROOF] items:** ...
```

For multi-section pages, show sections in order with labels (Hero, Problem, Solution, How it works, Proof, Offer, Guarantee, FAQ, Final CTA) and include direction for visuals.

## 4. Variant labelling

Label every variant with its **angle** (Outcome, Risk reversal, Identity, Contrast, Mechanism, Story, Speed, Cost) and the **reader state** it targets. Never present three rewordings of one idea as three variants.

## 5. Test plan and proof-to-collect tables

Proof to collect:

| Proof needed | Why it matters | How to get it | Owner | Done |
|---|---|---|---|---|
| 5 customer quotes with a number | Replaces generic claims in hero | WhatsApp the last 20 buyers, ask 3 questions | Owner | [ ] |

Test plan: ranked list of tests using the template in `10-quality-and-testing.md`. The first three tests must be doable with the user's real traffic and budget.

## 6. Final summary format (what to say in chat)

Keep it short, in this order:

1. **What I found** (2 to 4 bullets: customer insight, competitor gap, biggest problem or risk).
2. **Positioning and angle I recommend** (one line each) and why.
3. **What I produced** (files, with paths).
4. **Needs your input:** assumptions to confirm, proof to collect, risks (including legal ones).
5. **Run these 3 tests first.**
6. **Next asset I can write** (offer 2 to 3 options).

Do not paste entire documents into chat unless asked; quote the headline set and the single most important asset.

## 7. Handoff notes

If a designer, developer, or media buyer will use the copy, add: layout/section order, character limits, image direction, tracking links or codes, and implementation notes (for example "WhatsApp button must prefill this message").

## 8. Editing an existing asset

1. Read the original and note its goal and audience.
2. Diagnose (use section 11 of `05-copy-craft.md`).
3. Rewrite, keeping what works (facts, brand voice, proven lines).
4. Show before and after with a short reason for each major change.
5. Flag any claims that need proof.
6. Keep edits minimal if the user asks for light touch; change only what they ask.
